    Appliance setup

    Appliance basic configuration

    1. Login to raptor and check local ip address of cm 
      cat /etc/hosts
    2. Login to cm cli using ssh session on raptor 
      ssh -lcli -p22 cm
    3. Run two commands to pause the data aggregation process. In the test environment, enabled aggregation services may cause unintended delays while waiting for several steps to be completed (the second command will require confirmation). 
      1
2
3
      store run_cleanup_orphans_daily off

store purge_age_period 0
    4. Display network interfaces and routes to verify connectivity. 
      1
2
3
      show network interface all

show network route default
    5. Notice that the IP address is set to localhost, which is specific to the IBM Cloud environment. Update the IP address to the correct value based on IP address identified in step 1. 
      store network interface ip <cm_ip_address>/24
    6. Check DNS resolver configuration. The list will be empty because the appliance is deployed in the cloud. 
      show network resolvers
    7. In this case, you can retrieve the dynamically assigned list of local servers using the following command. 
      show network resolvers_cloud
    8. Test external DNS resolution by pinging a public hostname. Do not interrupt the test with Ctrl+C, because this may terminate the ssh connection. 
      ping www.ibm.com
    9. Display the current system time settings. 
      show system clock all
    10. List available time zones. 
      store system clock timezone list
    11. Set the system time zone to lab timezone. Wait a few minutes until the change is fully applied. All machines in the lab will use GMT (Europe/London) time zone configuration. 
      store system clock timezone Europe/London
    12. Re-login to cli session on cm and confirm new time zone. 
      show system clock all
    13. Configure NTP servers (three pool.ntp.org servers) and enable the NTP client. 
      store system time_server hostname 0.pool.ntp.org 1.pool.ntp.org 2.pool.ntp.org
    14. Confirm that they are correctly set. 
      show system time_server all
    15. Activate NTP client, execute: 
      store system time_server state on
    16. Change the central manager host name to cm. When asked about cloning, answer “yes”. This command can take timeout (10 minutes). Then re-login and confirm than name was set to cm.yourcompany.com 
      store system hostname cm
    17. Set the domain name 
      store system domain demo.guardium
    18. Re-login and confirm that machine prompt is now set to cm.demo.guardium.
    19. Restart network, insert Yes to confirm 
      restart network
    20. Because we have multiple cloned appliances in our environment and all share the same Guardium ID (GID), assign a unique ID to each of them before configuring them to work together, use the following command. 
      store product gid 1111
    21. All appliances in a centrally managed environment must share the same shared secret. Set it to "guardium" on cm. 
      store system shared secret guardium
    22. Set cm configuration to accept small disk. 
      store system small_disk
    23. Increase GUI and CLI session timeouts to avoid unexpected logouts. 
      1
2
3
      store gui session_timeout 9999

store timeout cli_session 600
    24. Display the static host mappings; initially this list is empty. 
      support show hosts
    25. Add static host entries for all lab machines (coll1, appnode1, appnode2, kafka1, raptor, sauropod, ceratops)

support store hosts <appnode1_ip_address> appnode1.demo.guardium

support store hosts <raptor_ip_address> raptor.demo.guardium

support store hosts <sauropod_ip_address> sauropod.demo.guardium

support store hosts <ceratops_ip_address> ceratops.demo.guardium
    26. Display the host list again and confirm that all entries are correctly configured. 
      support show hosts
    27. Restart the cm. If the appliance reports that MySQL is archiving, choose “No” to abort the restart and try again later, as shown in the screenshot. 
      restart system
    28. Reconnect to the cm and check appliance unit type. The appliance is an aggregator and is not yet configured as a central manager. 
      show unit type
    29. The system has valid license keys loaded, so you can now promote the aggregator to be a Central Manager. This command may take some time as it activates all services required for managing the appliance group 
      store unit type manager
    30. You can proceed with the next part of the lab and return to this CLI session once the command above is completed. Then verify that the aggregator has been successfully promoted to a manager. 
      show unit type

    Add user and create dashboard

    1. Login to cm UI as an accessmgr user (use this same password like you used for cli access to appliances) and press Add User button in Access manager view
    2. Create a new user - demo. Set password and description. Expand the Roles panel and select: admin, cli, fam, user and vulnerability assessment roles.
    3. Scroll slightly down, select Password never expires, then click Add to create the user.
    4. The newly created user should appear at the bottom of the list. Then, use the State toggle for the guardium account to deactivate it.
    5. Sign out of the accessmgr account and sign in as the newly created demo user.
    6. In the Search field, enter License to filter the options. Select the License view and review the installed license keys. The Central Manager, as mentioned earlier, has pre-installed license keys for a centrally managed environment. Functional (append) keys enable DAM, FAM and VA features.
    7. Navigate to the Feature Unlock tab and verify that the additional features have been loaded into the system. Note that this does not mean they have been activated.
    8. Next, select Definition Export/Import, go to the Import tab, choose the report definition file exp_full_sql_report.sql from your exports folder (student materials), and click Upload file.
    9. After a moment, the Full SQL (Training) report should appear in the Uploaded files section. Select it and click Import.
    10. After a moment, a confirmation message should appear indicating the report was successfully imported.
    11. Repeat the import process, but this time use the exp_default_policy.sql file. This will load the policy named Default bootcamp policy.
    12. To create a dashboard, select the pencil icon from the vertical menu, then choose Create New Dashboard. Edit the name to Training and click Save. Next, click Add Report to open the report selection window and add three reports: the newly imported Full SQL (Training) and the built-in SQL Errors and S-TAP and External S-TAP Statistics. Reports are added to the dashboard upon selection from the list.
